1 背景描述
平台已有测试机状态监控（探针心跳），但自动化测试的进度与结果数据只存在于测试机本地，平台不可视，查询依赖线下询问/登录测试机查看日志；需补齐"机器状态 → 测试进度/结果"的监控闭环。

2 业务目标
打通自动化测试"主动上报 → 平台持久化 → 按 Build 分组可视化展示"的进度闭环，实现测试进度自助实时查看；成功指标：上报后 30 秒内平台可见最新进度，同一测试运行重复上报仅更新进度、不产生重复记录。

3 业务逻辑变更
当前行为：测试进度仅在测试机本地日志中，平台"测试机状态"页只展示心跳，不展示测试内容与进度。
期望行为：新增上报接口 POST /api/test-results/report（共享探针令牌 X-Probe-Token 认证，无用户会话可调用）；平台持久化存储后，前端新增"测试结果"页按 Build 分组展示各测试运行的进度条与状态，支持筛选、分页、手动刷新与 30 秒自动刷新。
业务规则：BuildNumber + TestType + TestMachine 联合唯一键，重复上报为 upsert（仅保留最新状态）；字段兼容 PascalCase/snake_case 与数字/字符串构建号，未知字段忽略；错误/缺失令牌返回 401，未配置返回 503；仅保留最新进度，不做历史流水。

4 测试用例
核心测试场景：首次上报新联合键返回 created: true；同键重复上报返回 created: false 且进度更新、记录 id 不变；认证异常 401/503；字段兼容（数字/字符串、两种键名、未知字段不报错）；查询接口分组、排序、筛选、分页正确；前端分组渲染、进度条、状态标签与刷新功能可用。
回归测试范围：测试机探针端点 /api/test-machines/probe 行为与错误码不变；测试机状态页现有功能不受影响；前端构建（npm run build）通过。

5 验收标准
上报认证与去重行为正确（401/503、created 标识、id 不变）；字段兼容性与未知字段容错符合预期；查询接口按 Build 分组、构建号倒序、组内排序正确；前端页面渲染、筛选、分页、刷新均可用；前端构建通过；现有探针功能不受重构影响。
验收方式：演示+测试
