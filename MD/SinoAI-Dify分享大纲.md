## SinoAI Platform & Dify 内部分享大纲

> 面向：组内开发 & 测试同事 | 时长：60 分钟 | 目标：了解能力 → 学会使用 → 理解架构 → 收集反馈分工

---

### 开场：为什么做这件事（5 分钟）

> gstack 框架：Office Hours — 问题验证

**核心叙事**：从"大家日常遇到的痛点"出发，而不是从技术出发。

- 一个场景引入：描述一个公司内真实存在的、AI 可以解决但之前没解决的场景（如：反复回答同类问题、手动整理文档、缺少统一的 AI 调用入口等）
- 点明目标：我们要做的不是"部署一个工具"，而是给公司一个**可复用、可管控、可持续演进的 AI 能力平台**
- 引出两个关键词：**SinoAI Platform**（统一入口 + 身份管理 + Skills 市场）和 **Dify**（AI 引擎 + Agent 编排）

---

### 第一部分：全景架构——两个系统如何协作（10 分钟）

> gstack 框架：Engineering Review — 架构设计 + CEO Review — 战略定位

**1.1 一句话定位**

**1.2 为什么是这两层？（技术决策同步）**

- Dify 负责"AI 重活"：模型调用、Agent 编排、知识库检索、工作流执行——这些是通用能力，不需要重复造轮子
- SinoAI 负责"公司特色"：身份认证（谁是谁）、权限管控（谁能用什么）、Skills 市场（能力发现和复用）——这些是公司业务强相关的差异化层
- 这种分层的好处：Dify 社区持续更新，我们可以跟着升级；SinoAI 聚焦业务层，不被底层 AI 细节拖累

**1.3 技术栈一览**

用一张表格快速过：SinoAI 的技术栈、Dify 的技术栈、部署方式（Docker Compose）、模型配置（本地 + 外部混合）。对开发同事重点提一下关键组件版本和依赖关系。

### 第二部分：SinoAI Platform 能力详解（12 分钟）

> gstack 框架：Design Review — 用户旅程 + Engineering Review — 模块边界

**2.1 身份管理（3 分钟）**

- 解决什么问题：Dify 原生没有企业级身份管理，SinoAI 补上了这一环
- 怎么做的：SSO 对接 / 角色权限（RBAC）/ 部门隔离
- 对开发同事的意义：后续接入内部系统时，身份链路是通的，不需要每个系统单独做登录
- 对测试同事的意义：可以按角色测试不同权限场景

**2.2 Skills 市场（5 分钟）**

- 解决什么问题：AI 能力散落在各处，没人知道有什么可以用、该怎么用
- 怎么做的：把 Dify 中的 Agent / 工作流 / 应用统一包装成"Skill"，分类展示，一键调用
- 类比：类似 App Store 的概念——开发者发布 Skill，使用者在市场中发现和安装
- 对开发同事的意义：你构建的 Agent 可以通过 Skills 市场被全公司看到和使用
- 对测试同事的意义：Skills 市场本身需要测试（发布流程、权限控制、调用链路）

**2.3 统一前端入口（4 分钟）**

- 用户视角：一个界面完成所有 AI 交互，不需要分别登录 Dify 后台和其他系统
- 展示前端界面的核心页面：首页/对话页、Skills 浏览页、个人中心
- 快速过一下前端技术实现要点（给开发同事参考）

### 第三部分：Dify 核心能力详解（13 分钟）

> gstack 框架：Engineering Review — 数据流 + 功能覆盖

**3.1 Agent 编排能力（5 分钟）**

- Dify 中的 Agent 是什么：可以理解为"配置出来的 AI 助手"，有角色设定、知识库、工具调用能力
- 编排方式：可视化配置（选模型 → 设提示词 → 挂知识库 → 加工具），不需要写代码
- 展示一个已经配好的 Agent 实例，说明配置项之间的关系
- 对开发同事的意义：你可以快速验证一个 AI 场景是否可行，不需要从零写代码

**3.2 工作流引擎（4 分钟）**

- 解决什么问题：复杂的 AI 任务不是一步完成的，需要多步编排（如：检索 → 总结 → 格式化 → 发送）
- Dify 工作流的可视化编排界面：节点式拖拽，支持条件分支、循环、变量传递
- 展示一个实际的工作流案例
- 对开发同事的意义：复杂业务逻辑可以拆解成工作流节点，每个节点独立调试

**3.3 RAG 知识库（4 分钟）**

- 原理简述：文档 → 切片 → 向量化 → 存储 → 检索 → 注入上下文 → 模型回答
- 当前已导入的知识库情况
- 检索效果演示（同一个问题，有知识库 vs 没有知识库的回答对比）
- 对测试同事的意义：RAG 的检索质量需要持续测试和优化（切片策略、召回率、准确性）

### 第四部分：Live Demo 实操演示（12 分钟）

> gstack 框架：Office Hours — 快速验证，让用户看到真实效果

**Demo 1：作为普通用户使用（3 分钟）**

- 登录 SinoAI → 进入对话 → 提问一个和公司业务相关的问题 → 展示知识库增强的回答效果
- 浏览 Skills 市场 → 选择一个 Skill → 使用

**Demo 2：作为开发者创建一个 Agent（5 分钟）**

- 进入 Dify 后台 → 创建一个新的聊天助手
- 配置：选模型 → 写提示词 → 关联知识库 → 测试对话效果
- 发布为 Skill → 在 SinoAI 前端看到它出现在 Skills 市场中
- 展示完整的"从创建到使用"链路

**Demo 3：工作流编排演示（4 分钟）**

- 展示一个工作流的编辑界面
- 逐步讲解节点连接和执行逻辑
- 运行一次，展示中间过程和最终输出

### 第五部分：接入指南 & 协作分工（8 分钟）

> gstack 框架：Retro — 团队协同 + Engineering Review — 可维护性

**5.1 开发同事怎么参与（3 分钟）**

- 接入方式概览：通过 Dify API 将 AI 能力集成到自己的业务模块中
- API 入口和认证方式（通过 SinoAI 统一鉴权）
- 代码仓库位置、开发环境搭建步骤
- 建议的接入优先级：先调通一个最简单的 Agent → 再尝试工作流 → 最后发布为 Skill

**5.2 测试同事怎么参与（3 分钟）**

- 需要测试的维度：功能测试（Agent 对话、工作流执行）、权限测试（不同角色的可见范围）、性能测试（并发对话响应时间）、质量测试（RAG 检索准确率）
- 测试环境和生产环境的区分
- Bug 反馈渠道和优先级定义

**5.3 近期计划 & 分工征集（2 分钟）**

- 第二阶段目标：扩展 Skills 市场品类、完善权限体系、对接更多内部系统
- 开放认领的任务方向（举例）：
  - 开发：构建 2-3 个业务场景的 Agent / 工作流
  - 测试：编写 Agent 对话质量评测用例 / 性能基准测试
  - 所有人：提出你希望 AI 解决的实际场景

### 收尾：Q&A 和自由讨论（12 分钟）

> gstack 框架：Retro — 反馈收集

**预留充足时间给互动：**

- 开放提问（5 分钟）：解答技术细节、使用疑问
- 收集反馈（4 分钟）：
  - "你觉得哪个功能对你最有用？"
  - "你最希望 AI 帮你解决什么问题？"
  - "你觉得当前最大的障碍是什么？"
- 下一步约定（3 分钟）：
  - 明确后续同步节奏（如每周一次进展同步）
  - 建立沟通群/频道
  - 约定第一次协作交付的时间节点
